# Імпорт Excel та BI аналітика

Модуль `bi-service` на Java 17 і Spring Boot 3.5.15 зберігає пакетно імпортовані звернення в таблиці PostgreSQL `bi_contact_records`. Vue-сторінка `/analytics` використовує Axios і Chart.js 4.6.1. Дані BI відокремлено від CRUD-звернень основного сервісу: це окремий набір для імпорту й аналітики, а не синхронізована копія `tickets`.

Для читання `.xlsx` використовується Apache POI 6.0.0 (`poi-ooxml`). Це актуальний реліз замість наведеної в прикладі завдання 5.2.3. Джерело: https://poi.apache.org/download.cgi.

## Формат Excel

Один аркуш, перший рядок — заголовок. Колонки саме в такому порядку:

| Колонка | Тип та обмеження |
|---|---|
| Код | Унікальний текст, 1–40 символів: латинські літери, цифри, `_`, `-` |
| Тема | Текст, 1–200 символів |
| Категорія | Текст, 1–80 символів |
| Статус | `NEW`, `IN_PROGRESS`, `RESOLVED`, `CLOSED` |
| Дата | Дата Excel без часу або текст `РРРР-ММ-ДД`, роки 2000–2100 |
| Тривалість хв | Ціле число 0–1440 |

Формули та логічні клітинки не приймаються. Порожні рядки пропускаються. Максимум 2000 рядків після заголовка та 2 МБ на файл. Перевіряються розширення й фактична можливість відкрити файл через `XSSFWorkbook`; перейменований текстовий файл відхиляється.

Весь файл перевіряється перед `saveAll`. Імпорт виконується в транзакції. Помилка в будь-якому рядку або повторний код скасовує весь пакет. Унікальний індекс PostgreSQL захищає також від одночасних імпортів однакових кодів. Для виправленого повторного імпорту необхідні нові коди; автоматичного оновлення наявних записів немає.

## HTTP API

Базова адреса локально: `http://localhost:8083/api`.

| Метод | Шлях | Результат |
|---|---|---|
| POST | `/import/excel` | Multipart-поле `file`; 201 з `imported` і `skipped` |
| GET | `/import/template` | Файл `template.xlsx` з одним прикладом |
| GET | `/analytics` | `total`, `totalMinutes`, `categories`, `statuses`, `dates` |

Помилки імпорту: 400 — формат, заголовки чи значення; 409 — конфлікт кодів із БД; 413 — завеликий файл. `detail` у JSON ProblemDetail пояснює помилку, для рядків наводиться їхній номер Excel.

Приклад успішного імпорту: `{"imported":12,"skipped":0}`. Кожна статистична група має вигляд `{"label":"Картки","count":3}`. Агрегація виконується PostgreSQL через JPQL `GROUP BY`; `REPEATABLE_READ` забезпечує узгоджений знімок для всіх запитів однієї відповіді.

Діаграми показують усі імпортовані записи. Bar Chart — кількості за категоріями. Pie Chart — розподіл за статусами; відсотки наведені під діаграмою. Частка вирішених та закритих дорівнює `(RESOLVED + CLOSED) / total × 100`. Дати додатково відображаються в таблиці. Після POST клієнт повторно виконує GET, тому діаграми беруть дані з БД. Якщо GET не вдався, застарілі графіки приховуються й доступна кнопка повторення; підтвердження успішного імпорту зберігається.

Chart.js створюється в `onMounted`, оновлюється через `watch` і `update`, звільняється через `destroy` в `onBeforeUnmount`. API Chart.js: https://www.chartjs.org/docs/latest/developers/api.html.

## Контрольний набір

`fixtures/lab6/template.xlsx`: 12 синтетичних звернень за 01–03.11.2026. Чотири категорії по 3 записи, статуси CLOSED — 4, RESOLVED — 4, NEW — 2, IN_PROGRESS — 2; по 4 звернення щодня. Сума тривалості — 114 хв, частка вирішених і закритих — 66,7%.

Workflow `verify-bi.yml` перевіряє імпорт на PostgreSQL 17, збирає Vue всередині корпоративного JAR, запускає BI та основний сервер і виконує браузерні тести. Він не звертається до OpenAI й не витрачає API-баланс.
